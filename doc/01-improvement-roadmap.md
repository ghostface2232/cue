# Cue 제품·UX·디자인 개선 로드맵

> 기준일: 2026-08-13<br>
> 분석 기준: `main` / `df8a29e`<br>
> 범위: 제품 구조, 실제 실행 UI, XAML·ViewModel·저장소 코드, 테스트·CI, 커밋·릴리스 기록

## 결론

Cue의 기반은 이미 단단하다. 파일이 원본이고 SQLite가 재생성 가능한 인덱스라는 원칙, 한국어 날짜 파서, 반복 일정의 occurrence-record 모델, 비동기 자동 저장, 626개 테스트는 foundation 단계에서 가장 위험한 데이터 계층을 잘 방어한다. 지금 가장 큰 기회는 새 기능의 수를 늘리는 것이 아니라 **“한 줄로 잡고 → 키보드로 정리하고 → 오늘 할 일을 빠르게 처리하는” 핵심 루프를 완성하는 것**이다.

다음 순서를 권장한다.

1. **Now — 찾기와 키보드 흐름:** 검색, 전역 빠른 추가, 행 키보드 조작을 한 묶음으로 완성한다.
2. **Now — 첫 실행과 정보 구조:** 비어 있는 화면이 사용법을 가르치고, `언젠가`·`앞으로` 같은 핵심 보기가 숨지 않게 한다.
3. **Next — 밀린 일 정리와 일괄 작업:** Today에 쌓인 업무를 빠르게 재배치할 수 있게 한다.
4. **Next — 데이터 통제감:** 최근 삭제, 내보내기, 데이터 폴더 열기를 제공한다.
5. **Next — UI 구조와 회귀 방지:** 중복된 상세 패널을 공용 컴포넌트로 만들고 핵심 UI 시나리오를 자동화한다.

완전한 동기화, 협업, AI 비서, Area 계층은 아직 우선순위가 아니다. 현재 설계의 강점을 희석하지 않고 단일 기기 핵심 루프를 먼저 끝내는 편이 맞다.

## 우선순위 기준

| 단계 | 의미 | 권장 시점 |
| --- | --- | --- |
| Now | 핵심 사용 흐름과 첫인상을 직접 개선 | 다음 마이너 릴리스 |
| Next | 유지율과 장기 사용성을 높임 | 이후 1~2개 릴리스 |
| Later | 차별화와 확장 | foundation 종료 후 |

## Now 1. 검색 + 키보드 우선 작업 흐름

### 제안

- `Ctrl+F`: 현재 보기 검색을 열고, 범위를 `현재 보기 / 모든 할 일`로 바꿀 수 있게 한다.
- 1차 검색은 제목만 대상으로 작게 출시한다. 메모 검색은 인덱스 스키마 버전을 올리고 재빌드하는 2차 작업으로 분리한다.
- `Ctrl+N` 또는 `Q`: 어느 화면에서든 빠른 추가 입력으로 포커스를 이동한다.
- 행에서 `↑/↓` 이동, `Enter` 상세 열기, `Space` 완료/재열기, `Delete` 삭제를 지원한다.
- `Ctrl+,` 설정, 보기 전환 단축키를 제공하고 단축키 도움말을 한 곳에서 확인하게 한다.
- 빠른 추가에서 `/` 명령 팔레트로 그룹·태그·우선순위·종일 여부를 선택할 수 있게 한다. 이것은 날짜 파서 규칙을 늘리는 방식이 아니라 `QuickAddSubmission`의 out-of-band 메타데이터로 구현해 “우선순위/그룹/태그는 텍스트 파싱하지 않는다”는 불변식을 지킨다.

### 근거

- 현재 `ITaskIndex`에는 검색 쿼리가 없고 인덱스에 `notes` 열도 없다. `AGENTS.md`의 Index layer가 이를 명시한다.
- 행은 포커스를 받지만 키보드는 삭제만 처리한다: `Pages/TaskListPage.xaml.cs:236`, `Pages/WeeklyTimelinePage.xaml.cs:377`.
- 전역 `KeyboardAccelerator`는 핵심 캡처·검색 흐름에 연결돼 있지 않다.
- 제품 이름과 가치 제안이 “한 줄 입력으로 다음 행동을 cue한다”이므로, 포인터 없이 캡처부터 분류까지 끝나는 흐름이 제품 정체성과 가장 잘 맞는다.

### 완료 조건

- 키보드만으로 앱 실행 후 새 할 일 생성, 검색, 상세 열기, 완료, 재열기까지 가능하다.
- 10,000개 제목 데이터에서 검색 입력이 눈에 띄게 버벅이지 않는다.
- 검색 결과 없음, 현재 보기 비어 있음, 필터 결과 없음이 서로 다른 메시지를 제공한다.
- 스크린 리더가 검색 범위, 결과 개수, 선택 행, 완료 상태를 읽는다.
- 단축키로 여닫는 고빈도 UI에는 진입/퇴장 모션을 넣지 않는다.

## Now 2. 첫 실행·빈 상태·탐색 구조 재설계

실제 900×810, 150% 배율 실행에서는 첫 화면의 대부분이 빈 캔버스였고, 사이드바가 오버레이 상태로 시작했다. `앞으로`와 `언젠가`는 기본 숨김이며 사이드바 빈 영역의 우클릭 메뉴를 알아야 다시 보인다(`MainWindow.xaml.cs:580-591`). 특히 날짜 없는 빠른 추가가 도착하는 기본 버킷인 `언젠가`를 숨기는 것은 데이터 모델과 탐색 구조가 서로 어긋난다.

| Before | After |
| --- | --- |
| 제목, 정렬, 입력창, “여기에 표시할 할 일이 없어요”만 남은 큰 빈 화면 | “내일 오후 3시 치과 예약” 같은 2~3개 예시 칩과 `Enter로 추가` 안내가 첫 행동을 유도 |
| `앞으로`·`언젠가`가 기본 숨김이고 복구 기능은 배경 우클릭에 숨어 있음 | 두 보기를 기본 노출하거나, 명시적인 `탐색 편집` 버튼에서 숨김/순서를 관리 |
| 모든 빈 상태가 비슷한 문장 | 첫 실행 / 필터 결과 없음 / 완료 항목 없음 / 검색 결과 없음에 맞는 안내와 단일 CTA |
| 창의 물리 픽셀 기본 크기와 NavigationView의 DIP 임계값이 충돌 | 모니터 DPI를 반영한 초기 크기와 100/125/150/200% 배율별 검증 기준 |

### 권장 설계

- 최초 1회만 예시 입력 칩과 한국어 자연어 예시를 보여 준다. 실제 예제 할 일을 자동 생성하지 않는다.
- 입력 중 파싱 결과를 `내일 · 오후 3:00 · 반복`처럼 한 줄로 미리 보여 주어 신뢰를 높인다.
- 빈 상태의 CTA는 하나만 둔다. 예: `할 일 추가` 또는 `필터 지우기`.
- 사이드바 커스터마이징은 우클릭을 보조 경로로 유지하되, 설정 또는 `…` 메뉴에도 명시적으로 노출한다.
- 첫 실행 창 크기는 DIP 기준으로 계산하고 주 콘텐츠가 최소 Compact 상태 이상으로 보이게 한다.

### 완료 조건

- 신규 사용자가 설명 없이 30초 안에 날짜가 있는 첫 할 일을 만든다.
- 100/125/150/200% 배율과 1366×768 이상 화면에서 첫 실행 시 빠른 추가와 핵심 탐색이 동시에 보인다.
- 숨긴 보기를 포인터·키보드 양쪽에서 쉽게 복구할 수 있다.

## Next 1. 밀린 일 정리와 일괄 작업

Today는 미완료 과거 일정을 오늘로 끌어오도록 올바르게 설계돼 있다. 장기 사용에서는 이 장점이 “밀린 일 더미”로 바뀔 수 있으므로 정리 도구가 필요하다.

- 다중 선택 후 `오늘`, `내일`, 날짜 선택, `언젠가`, 그룹, 태그를 일괄 적용한다.
- Today 상단에 `밀린 일 N개`를 별도 접힘 섹션으로 보여 주고 `모두 내일로`, `날짜 다시 정하기`를 제공한다.
- 자연어 파서의 반복 규칙과 일괄 변경이 충돌하지 않도록, 반복 항목은 “이번 일정만 / 시리즈” 의미를 명확히 한다.
- 실행 취소 토스트는 마지막 일괄 작업 하나를 되돌릴 수 있어야 한다.

### 완료 조건

- 100개의 밀린 할 일을 개별 상세 패널 없이 날짜·그룹별로 정리할 수 있다.
- 일괄 작업은 각 레코드를 `ITaskStore` 단일 쓰기 경로로 저장하고, 중간 실패를 사용자에게 명확히 알린다.
- 반복 시리즈의 다음 주기와 과거 occurrence가 잘못 수정되지 않는 테스트가 있다.

## Next 2. 데이터 통제감: 최근 삭제·내보내기·폴더 열기

Cue의 “한 레코드 한 JSON 파일”은 기술 구현을 넘어 제품 차별점이 될 수 있다. 사용자가 이를 체감하도록 한다.

- 삭제 직후 실행 취소와 `최근 삭제된 항목` 보기를 제공한다.
- JSON 원본 폴더 열기, 전체 백업, Markdown/CSV 내보내기를 설정에 둔다.
- 복원은 tombstone을 제거하고 저장소와 인덱스에 반영하는 명시적 작업으로 구현한다.
- 데이터 루트와 로컬 인덱스 위치가 다른 이유를 짧고 이해하기 쉬운 문장으로 설명한다.

### 완료 조건

- 사용자가 앱 안에서 실수로 삭제한 작업·그룹·태그를 복원할 수 있다.
- 내보낸 파일은 앱을 설치하지 않은 환경에서도 읽을 수 있다.
- `index.db` 삭제 후 재시작 복구 테스트가 계속 통과한다.

## Next 3. 선택형 일일 브리핑

알림 문서에는 종일 작업을 일일 브리핑이 다룬다고 되어 있지만 기능은 아직 후속 단계다(`NOTIFICATIONS.md:9`, `NOTIFICATIONS.md:48`). 개별 종일 알림을 남발하기보다 이 방향이 Cue의 차분한 성격에 맞다.

- 기본은 꺼짐.
- 사용자가 정한 아침 시간에 `오늘 N개 · 밀린 일 M개` 한 건만 보낸다.
- 알림 클릭 시 Today로 이동한다.
- 앱이 꺼져 있어도 예약된 OS 알림이 동작하도록 하고, 시간대·DST 변경 시 예약을 다시 조정한다.

### 완료 조건

- 종일·시간 지정·밀린 항목의 포함 규칙이 문서와 테스트로 고정된다.
- 중복 알림이 없고, 알림 클릭이 정확히 Today 또는 해당 작업으로 이동한다.

## Next 4. 상세 패널을 공용 컴포넌트로 추출

현재 목록과 주간 타임라인에 상세 패널 XAML과 이벤트 처리가 중복돼 있다. `TaskListPage.xaml`과 `TaskListPage.xaml.cs`는 각각 1,000줄을 넘고, 주간 페이지에도 동일한 메모·체크리스트·반복 이력 UI가 복제돼 있다. 최근 테마 변경 커밋 `dac39ce`, `4a6945d`가 두 페이지와 여러 ViewModel을 함께 수정한 것은 이 중복이 실제 회귀 비용으로 나타난 사례다.

### 권장 경계

- `TaskDetailPane` UserControl: 헤더, 메타데이터, 메모, 체크리스트, 반복 타임라인.
- `TaskDetailHostBehavior` 또는 공용 coordinator: 열기/닫기, 너비 조절, 중앙 정렬, close 전 `FlushAsync`.
- 페이지는 선택된 TaskId와 host layout만 책임진다.
- 테마 변경, 저장 상태, 키보드 포커스 복원은 공용 컴포넌트 테스트 한 벌로 검증한다.

### 완료 조건

- 목록과 주간 타임라인에서 상세 패널의 XAML 템플릿이 한 곳에만 존재한다.
- 동일한 UI 동작을 두 페이지에서 각각 수정할 필요가 없다.
- 작업 전환 중 autosave, 실패 재시도, 창 닫기 flush 회귀 테스트가 유지된다.

## Next 5. UI 자동화와 접근성 품질 게이트

현재 CI는 단위 테스트, 빌드, 시작 스모크를 잘 수행하지만 실제 상호작용과 접근 가능한 이름은 검사하지 않는다. 이번 실행 검사에서 이름이 비어 있는 컨트롤이 발견된 이유도 이 계층이 자동화되지 않았기 때문이다.

최소 UI 스모크 묶음:

1. 빠른 추가로 제목+날짜 생성 후 목록에 표시.
2. 키보드로 행 열기·완료·재열기.
3. 알림 본문 클릭으로 해당 작업 상세 열기.
4. 150% 배율 첫 실행에서 핵심 탐색과 입력창 표시.
5. 주요 컨트롤의 `Name`, `ControlType`, `IsKeyboardFocusable` 검사.
6. 모션 끄기 상태에서 위치 이동 애니메이션이 실행되지 않는지 검사.

## Later. foundation 이후의 차별화

- **주간 회고:** 완료율 경쟁보다 “완료한 일, 미룬 일, 반복 흐름”을 차분하게 요약한다.
- **선택형 시작 프로그램/트레이:** 브리핑과 빠른 캡처에 명확한 가치가 생긴 뒤 추가한다.
- **클라우드 폴더 동기화:** 현재 per-record 파일과 tombstone 설계를 그대로 활용하되, 충돌 UI와 `UpdatedAt` 비교 정책을 먼저 제품화한다.
- **Area 계층:** 실제 사용자 데이터에서 그룹 수가 감당하기 어려워졌다는 근거가 생길 때 additive record로 추가한다.

## 커밋·릴리스 운영 개선

커밋 기록은 회귀를 빠르게 고치는 힘을 보여 주지만, 동일 기능의 추가·철회가 반복된 흔적도 있다. 예를 들어 수동 재정렬은 `eef77d1`에서 추가됐다가 `76920c9`에서 제거됐고, 이후 `9f5d0a3`에서 다시 추가됐다가 `2a5c46f`에서 다시 제거됐다. 이 자체가 잘못은 아니지만, 기능의 성공 조건과 불변식 검토가 구현 전에 더 선명하면 비용을 줄일 수 있다.

- 큰 상호작용은 구현 전에 1쪽짜리 decision note를 남긴다: 사용자 문제, 범위, 비범위, 데이터 불변식, 철회 기준.
- 문서의 각 항목을 GitHub Issue로 옮기고 `area/priority/risk` 라벨과 완료 조건을 붙인다. 현재 공개 저장소에는 열린 Issue와 PR이 없다.
- `v1.0.1` 이후 `main`에 알림·테마·완료 처리 수정이 누적돼 있으므로, 다음 릴리스에는 변경 로그와 수동 검증 체크리스트를 포함한다.
- 릴리스 체크리스트에 100/150/200% DPI, 밝게/어둡게/시스템 테마, 모션 끄기, 한국어 IME, 알림 활성화, index 재빌드를 고정한다.
